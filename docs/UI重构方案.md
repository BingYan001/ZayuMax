# 杂鱼Max (Zayu) — UI/UX 重构方案

> 目标：从「开源解析引擎的二次开发」变成「有独立灵魂的产品」。  
> 原则：**不重写业务能力，只重构信息架构、交互路径与视觉语言**。  
> 本文所有参数均对齐项目现有实现（`ui/glass/GlassTokens.kt`、`ui/theme/Color.kt`），可直接落地。



---

## 0. 先说结论：现状盘点与改造优先级

| 维度    | 现状                         | 差距                                    | 优先级    |
| ----- | -------------------------- | ------------------------------------- | ------ |
| 信息架构  | 底部 4 Tab：解析 / 网盘 / 下载 / 设置 | 是「工具分类」而非「用户意图分类」                     | **P0** |
| 首页形态  | 顶部输入框 + 大按钮（经典解析工具布局）      | 与开源原版观感趋同，无辨识度                        | **P0** |
| 视觉体系  | 玻璃参数已成型（`GlassTokens` 全套）  | 参数是**分散的经验值**，未成规范；品牌色仍是 Material 默认蓝 | **P0** |
| IP 形象 | 仅图标（初音吃西瓜）                 | 无贯穿，空状态/加载/失败都是通用图形                   | **P1** |
| 文案调性  | 中性技术描述（「提取码」「解析失败」）        | 无性格                                   | **P1** |
| 媒体库   | 有在线播放能力                    | 没有聚合入口，播放能力被埋没                        | **P1** |
| 下载可视化 | 线性进度条 + 文字                 | 无视觉重心，长列表信息密度低                        | **P2** |
| 跨盘搜索  | 无                          | 无                                     | **P2** |

**核心判断**：视觉不是主要问题（玻璃体系已经不错），**信息架构才是**。  
现在的 4 个 Tab 是**按功能模块切分的**（解析是动作、网盘是数据源、下载是队列、设置是配置），  
用户完成一次「找资源 → 存下来 → 看/下载」要跨 4 个 Tab 来回跳。这才是「工具感」的根源。

## 1. 首页（解析页）文字版线框图

### 1.1 现有布局的问题

```
┌─────────────────────────────┐
│  [输入框：粘贴分享链接____]  │ ← 顶部输入框
│  [ 提取码：____ ]            │
│                             │
│      ╔═══════════════╗      │
│      ║  🔍 开始解析  ║      │ ← 巨大按钮
│      ╚═══════════════╝      │
│                             │
│      （大片空白）            │
│                             │
├─────────────────────────────┤
│  解析  网盘  下载  设置      │
└─────────────────────────────┘
```

问题：① 「顶部输入框 + 中间大按钮」是**所有解析工具的标准长相**，一眼就辨识出原型；  
② 大片空白浪费首屏，而首屏本该是最宝贵的位置；  
③ 用户 90% 的场景是**从剪贴板来的**，输入框本身是多余的一步。

### 1.2 重构后：内容优先 + 零输入唤起

```
┌───────────────────────────────────────────┐
│  杂鱼Max            🔍      🔔            │ ← 顶栏极简：左标题 / 右「全局搜索」「公告」
│                                            │
│  ┌──────────────────────────────────────┐ │
│  │ 📋 检测到链接                        │ │ ← ★ 剪贴板智能卡：检测到即置顶
│  │ https://pan.quark.cn/s/abc***        │ │   「零输入」—— 用户不用点输入框
│  │                    [ 🔓 解锁 ]       │ │   一键进入解析，这是首屏的绝对重心
│  └──────────────────────────────────────┘ │
│                                            │
│  🕐 最近解析                               │ ← ★ 历史卡（横向滑动）
│  ┌────┐ ┌────┐ ┌────┐                     │   复访最高频的入口，从「网盘」Tab
│  │封面│ │封面│ │封面│  →                  │   提到首页，减少一次跳转
│  └────┘ └────┘ └────┘                     │
│                                            │
│  ☁️ 我的网盘                    管理 >     │ ← ★ 网盘健康度概览
│  ┌──────────────────────────────────────┐ │   每个平台一张小卡：登录态 + 容量
│  │ 夸克 ●已登录  │ 百度 ●失效  │ 迅雷 ○未登录│   「失效」用品牌警示色高亮，
│  └──────────────────────────────────────┘ │   点击直达重登（当前要跳 3 层）
│                                            │
│  🎬 继续观看                               │ ← ★ 媒体消费入口（详见 §2.3）
│  ┌──────────────────────────────────────┐ │   最近播放的 3 个文件，点击即播
│  │ ▶ 某部剧 S01E03        进度 ▓▓▓▓░░ 68%│ │
│  └──────────────────────────────────────┘ │
│                                            │
│                              ╭──────────╮ │ ← ★ 悬浮胶囊 FAB
│                              │  ➕ 解锁 │ │   点击：半屏 BottomSheet 手输链接
│                              ╰──────────╯ │   长按：直接读剪贴板
├───────────────────────────────────────────┤
│      ╭─────────────────────────╮          │ ← ★ 悬浮胶囊导航（见 §2.1）
│      │ 首页  文件库  传输  我的 │          │
│      ╰─────────────────────────╯          │
└───────────────────────────────────────────┘
```

**首屏信息优先级**（从上到下，就是用户的决策顺序）：

1. **有没有现成的链接可用** → 剪贴板卡（有才显示，无则整块消失，不占位）
2. **上次在看什么** → 最近解析
3. **我的账号还好吗** → 网盘健康度
4. **上次看到哪了** → 继续观看

**手机号/链接输入从「常驻控件」降级为「兜底入口」**：  
悬浮 FAB → 半屏 BottomSheet：

```
╭───────────────────────────────────────╮

│  🔓 解锁链接                          │

│  │           🔓 解锁                │  │
│  ╰─────────────────────────────────╯  │
│                                       │
│  支持：夸克 · UC · 迅雷 · 百度 ·      │
│        139 · 123 · 115 · 光鸭 · 蓝奏  │
╰───────────────────────────────────────╯
```

**关键交互改进**：

- `IME action = Go`：软键盘回车直接触发解锁，不用抬手点按钮
- 粘贴时**自动识别提取码**：链接形如 `xxx?pwd=abcd` 或尾部四字符，自动拆到「暗号」框并提示「已自动填好暗号」
- 剪贴板卡出现时有**微动效**（从上方滑入 + 玻璃高光扫过），而不是生硬弹出

## 2. 三大核心页面的交互优化

### 2.1 导航：Tab 语义从「功能」改为「意图」

| 现在 | 改为      | 理由                                                 |
| -- | ------- | -------------------------------------------------- |
| 解析 | **首页**  | 「解析」是动作，不是位置。首页承载剪贴板检测 + 历史 + 概览                   |
| 网盘 | **文件库** | 「网盘」暗示"管理账号"，而用户真正要的是"我的文件"。文件库 = 所有平台的聚合视图 + 媒体消费 |
| 下载 | **传输**  | 「传输」天然涵盖上传/下载/离线任务的语义，为后续扩展留口；也去掉了「下载器」的工具味        |
| 设置 | **我的**  | 个人中心：账号矩阵、存储用量、外观、关于。设置只是「我的」里的一部分                 |

**视觉形态：悬浮胶囊导航**（替换现在的 `ShortNavigationBar`）

```
现状：贴底整条不透明条，占满宽度，分割线明显 → 「系统组件」观感
改为：100dp 高度的悬浮胶囊，左右各留 24dp，圆角全圆（Height/2），GlassTokens.STANDARD
     选中项：图标 + 文字同时展开（胶囊内宽度由内容撑开，避免文字被裁——这个坑已修，见 §4）
     未选中：仅图标，灰化
```

导航栏与内容区之间留 12dp 间隙，让玻璃折射背景图，避免"贴在屏幕上"的廉价感。

**长按导航项 = 快捷入口**（当前已实现长按放大，可在此基础上叠加）：

- 长按「传输」→ 直接弹出「暂停全部 / 继续全部」菜单
- 长按「文件库」→ 直接切到「最近播放」

### 2.2 传输页（原下载页）

**问题**：现在是一维列表，每行一个进度条，下载中的和已完成的长得一样，找东西靠滚。

**改为「双区 + 环形进度」**：

```
┌───────────────────────────────────────┐
│  传输                    全部 ▾   ⏸  │
│                                        │
│  ── 进行中 (2) ──────────────────────  │ ← ★ 进行中放大展示
│  ╭──────────────────────────────────╮ │
│  │      ╭─────────╮                  │ │
│  │      │  ◜◝◜◝   │  某电影.2026.mkv │ │ ← ★ 环形进度 + 动态光晕
│  │      │   67%    │  8.4 MB/s       │ │   光晕随速度呼吸（快=亮）
│  │      │  ◟◞◟◞   │  剩余 3 分 12 秒 │ │
│  │      ╰─────────╯                  │ │
│  │  ▓▓▓▓▓▓▓▓▓▓░░░░░░░░  ▓▓▓░░░░░░░  │ │ ← 分片可视化：每格=一个分片
│  │  8 线程 · 6 活跃 · 2 抢占重连     │ │   （引擎已有此数据，仅未展示）
│  │  [⏸] [✕] [📁]                     │ │
│  ╰──────────────────────────────────╯ │
│                                        │
│  ── 已完成 (14) ──────────── 折叠 ⌄ ──  │ ← ★ 已完成折叠收起
│  ✓ 文件A.mkv        1.2GB   10:23      │   单行紧凑，右侧「打开 / 定位」
│  ✓ 文件B.zip        340MB   昨天       │
│  ✓ 文件C.mp4        2.1GB   昨天       │
└───────────────────────────────────────┘
```

**为什么环形 + 分片可视化**：

- 环形进度在**同一视觉面积内**承载更多信息（百分比 + 速度 + 剩余时间三层）
- 分片格子图直接暴露引擎的**实际工作状态** —— 这正是"我们的引擎比原版强"的可视化证明。  
  用户看到 8 个格子有 6 个在跑、2 个在重连，会直观感到"这引擎在认真干活"
- 数据都已存在：`DownloadStats` 有 `activeWorkers`，`DownloadManager` 里有 `InflightChunk`（start/size），  
  `sampleInflightChunks` 已经在采样 —— **只差一个渲染层**

**已完成折叠**：默认折叠成单行，点击展开。列表滚动时"进行中"区**吸顶**。

### 2.3 文件库（原网盘页）→ 媒体消费中心

**现在的网盘页是「账号 + 文件树」**，本质是文件管理器。但项目支持在线播放，  
这意味着一件更重要的事：**它其实是个内容消费产品**。

**改为「三段式」**：

```
┌───────────────────────────────────────┐
│  文件库                    🔍 跨盘搜索 │
│                                        │
│  ── 继续观看 ────────────────────────  │ ← ★ 首屏第一屏
│  ┌──────────┐  某部剧 S01E03            │   大卡片：封面 + 进度条
│  │  封面    │  ▓▓▓▓▓▓▓░░░ 68%         │   点击直达播放位置
│  │  ▶       │  还有 12 分钟            │
│  └──────────┘                          │
│                                        │
│  ── 最近播放 ────────────────────────  │ ← 横向滑动
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐           │
│  │    │ │    │ │    │ │    │  →        │
│  └────┘ └────┘ └────┘ └────┘           │
│                                        │
│  ── 我的网盘 ────────────────────────  │ ← 这里才回到"账号/文件"
│  ● 夸克    已登录    ▓▓▓░░░ 156/800G   │
│  ● 百度    ⚠ 登录失效  → 点击重登       │ ← 失效用品牌警示色
│  ● 迅雷    已登录    ▓▓░░░░ 42/50G     │
│  ○ 115     未登录    → 点击登录         │
│                                        │
│  ── 全部文件 ────────────────────────  │ ← 原文件树，收进「更多」
│  夸克 › 我的分享 › ...                  │
└───────────────────────────────────────┘
```

**跨盘搜索**（P2，但架构上要预埋）：  
搜索框点击后进入全屏搜索页，输入关键词 → **并发查所有已登录平台** → 结果按「平台 / 类型 / 时间」分组。  
技术上：各平台的 `listFiles` 已有，需要加一个聚合层 + 结果缓存（Room 加一张 `IndexedFileEntity`）。  
**建议先做「文件名索引」而非实时查询** —— 实时查 6 个平台会很慢且触发风控。  
索引策略：在**空闲时**（充电 + Wi-Fi）后台增量扫描各平台文件列表，落 Room，搜索走本地 FTS。

## 3. 品牌色与设计规范

### 3.1 现状问题

`ui/theme/Color.kt` 里是 **Material 默认蓝** `primaryLight = Color(0xFF415F91)`，  
而玻璃背景是**粉色渐变 + 动漫图**。蓝色主题 + 粉色背景 = 两套语言打架，  
这就是"随意拼凑感"的来源（需求里也提到了）。

### 3.2 品牌色：薄荷青绿主色 + 粉色仅作氛围

需求提到「薄荷绿/青绿 + 深灰」作为点缀色，这个方向是对的 —— 它与粉色背景形成**冷暖对撞**，  
而且青绿色天然传达"高速/清爽"，契合下载工具的产品调性。

```kotlin
// 建议写入 ui/theme/Color.kt，替换现有 primaryLight 系
object ZayuPalette {
    // ---------- 品牌主色：薄荷青绿 ----------
    val MintPrimary        = Color(0xFF1FB6A6)  // 主色（按钮、选中态、进度条）
    val MintPrimaryDeep    = Color(0xFF0E8C7F)  // 主色深（按下态、深色主题下的主色）
    val MintContainer      = Color(0xFFB8F0E8)  // 主色容器（浅底、Chip 底）
    val MintGlow           = Color(0x331FB6A6)  // 主色微光（环形进度外发光）

    // ---------- 氛围色：粉（只用于背景，不进控件） ----------
    val BlossomPink        = Color(0xFFF5A9C8)  // 背景渐变起点
    val BlossomPinkDeep    = Color(0xFFE87BA8)  // 背景渐变终点
    // ★ 纪律：粉色永远只出现在「背景 / 装饰」，绝不用于按钮、文字、进度。
    //   品牌色与氛围色分离，是摆脱"杂乱"的关键。

    // ---------- 中性：暖深灰（不用纯黑/纯白） ----------
    val InkText            = Color(0xFF1C1F22)  // 主文字
    val InkTextSecondary   = Color(0xFF5A6169)  // 次文字
    val InkSurface         = Color(0xFFF7F9FA)  // 浅色主题基底

    // ---------- 语义色（与品牌色刻意区分） ----------
    val WarnAmber          = Color(0xFFF5A524)  // 警告（登录失效、限速中）
    val SuccessGreen       = Color(0xFF2FB344)  // 成功（下载完成）
    val DangerRed          = Color(0xFFE5484D)  // 错误
}
```

**关键纪律**：

- **主色只出现在「可交互 / 有状态」的元素上**（按钮、选中 Tab、进度、开关）。  
  背景、装饰、分割线一律不用主色 —— 这条守住了，界面就不会花。
- 粉色**降级为背景氛围**，不再出现在任何控件上。这条直接解决"杂乱无章"。

> **注意（A 股配色约定）**：项目里若出现涨跌类数据展示，**涨用红、跌用绿**。  
> 本方案的 `SuccessGreen / DangerRed` 是通用语义，与股市配色无关，两者不要混用在同一页面。

### 3.3 圆角规范（统一收敛）

现状：项目里圆角值散落（20dp / 16dp / 24dp 等）。建议固定为**四档**：

```kotlin
object ZayuShapes {
    val Card    = 20.dp   // 大卡片、弹窗容器
    val Item    = 14.dp   // 列表项、输入框
    val Chip    = 999.dp  // 胶囊（Chip、悬浮导航、FAB）—— 全圆
    val Thumb   = 10.dp   // 缩略图、封面小图
    // 嵌套规则：子元素圆角 = 父元素圆角 - 内边距，避免"圆角套圆角"的错位感
}
```

### 3.4 玻璃材质规范（把现有经验值固化为规范）

现有 `GlassTokens.kt` 的参数已经不错，但**没有"什么场景用哪一档"的规定**。  
补上这一层，从"随意拼凑"变成"规范"：

| 层级              | 用途                          | blurRadius | surfaceAlpha (亮/暗) | borderAlpha (亮/暗) | 圆角           |
| --------------- | --------------------------- | ---------- | ------------------ | ----------------- | ------------ |
| **Tier 1 — 浮层** | BottomSheet、Dialog、悬浮导航、FAB | 20dp       | 0.42 / 0.30        | 0.55 / 0.18       | Chip / Card  |
| **Tier 2 — 卡片** | 内容卡（剪贴板卡、网盘卡、播放卡）           | 18dp       | 0.32 / 0.24        | 0.62 / 0.22       | Card         |
| **Tier 3 — 内嵌** | 卡片内部的小块（Chip、缩略图底）          | 7dp        | 0.32 / 0.24        | 0.62 / 0.22       | Item / Thumb |

**层级纪律**：

- **同一屏最多两级玻璃**。三层玻璃叠在一起（浮层里套卡片再套小块）会导致模糊叠加、  
  文字发虚 —— 这是玻璃 UI 最典型的翻车点。
- **文字永远在玻璃之上，不在玻璃里**。不要在 `drawBackdrop` 的作用域里画文字，  
  否则模糊会连带文字一起糊掉。
- **玻璃必须有东西可折射**。纯色背景下玻璃 = 半透明色块，毫无意义。  
  所以背景渐变/图片必须铺满，玻璃才有存在价值。


### 3.5 字体

保持系统默认字体族（不引入自定义字体，避免包体膨胀与中文回退问题），
**只改字阶与字重**：

```
大标题     24sp / SemiBold   （页面标题、卡片主标题）
小标题     17sp / Medium     （列表项标题、段头）
正文       15sp / Regular    （描述、说明）
辅助       13sp / Regular    （时间戳、次要信息、灰色）
数字       等宽 or Medium    （速度、大小、百分比 —— 数字要"对齐感"）
```

**关键**：**下载速度/大小/百分比必须用等宽数字**（`FontFeatureSetting "tnum"`），
否则数字跳动时宽度变化会导致整行抖动（现在的下载页就有这个观感问题）。

## 4. 代码结构上的独立化思路

### 4.1 现状

包名 / 类名已经完成 `com.yunx.* → com.zayu.*` 的全量迁移（263 个文件），
**这部分独立性已经达成**。剩下的是**结构层面**的独立性 —— 即"一眼看出这是自己的架构"。

### 4.2 建议：按「领域」重组，而不是按「技术分层」

现在 `ui/screens/` 下平铺了 40 个文件（`XxxAccountSheet` / `XxxCloudScreen` / `XxxSaveSheet` × 9 个平台），
这是**技术分层**思路，加一个平台要动 3 处、散 3 个文件。

建议重组为**按平台聚合的垂直切片**：

```
com.zayu.app/
├─ core/                          # 引擎能力（与原版差异最大的地方，独立成 core）
│   ├─ download/                  # DownloadManager / ChunkDownloader / ElasticAllocator
│   ├─ net/                       # HttpClients / FastestIpDns / WebCookieJar / SessionKeeper
│   └─ security/                  # CredentialCipher / TextCipher
│
├─ drive/                         # ★ 网盘能力：一个平台一个包，自包含
│   ├─ quark/                     #   QuarkApi + QuarkAccountSheet + QuarkCloudScreen + QuarkSaveSheet
│   ├─ uc/
│   ├─ xunlei/                    #   XunleiApi + ... + XunleiUaProfile（本次新增）
│   ├─ baidu/
│   ├─ pan115/  pan123/  c139/  guangya/  lanzou/  ilanzou/
│   └─ DriveRegistry.kt           #   平台注册表：平台列表、图标、能力声明集中一处
│
├─ feature/                       # ★ 用户意图（对应新导航 Tab）
│   ├─ home/                      #   首页（剪贴板检测 + 最近 + 概览）
│   ├─ library/                   #   文件库 + 媒体库 + 跨盘搜索
│   ├─ transfer/                  #   传输（下载队列 + 环形进度）
│   └─ profile/                   #   我的（账号矩阵 + 外观 + 关于）
│
├─ design/                        # ★ 设计系统（独立成模块，可被 future 模块复用）
│   ├─ ZayuPalette.kt             #   品牌色（§3.2）
│   ├─ ZayuShapes.kt              #   圆角（§3.3）
│   ├─ ZayuTypography.kt          #   字阶（§3.5）
│   ├─ glass/                     #   玻璃宿主 + Tokens（现有 ui/glass/ 迁入）
│   └─ component/                 #   ZayuCard / ZayuChip / ZayuRingProgress ...
│
└─ mascot/                        # ★ IP 形象资源与组件（见 §5）
```

**这套结构的独立性体现在**：
1. **`core/` 与 `drive/` 的边界清晰** —— 引擎不认识任何网盘，网盘不知道下载怎么实现，
   靠接口对接。这个边界一划出来，架构就"有观点"了，不再是平铺的功能堆叠。
2. **`design/` 是可复用模块** —— 有自己的色板、形状、字体、组件，别的地方能拿去用。
   这是"产品化"的标志：你有一套设计系统，而不是一堆写死的颜色值。
3. **`feature/` 按用户意图命名** —— 直接对应导航的 4 个 Tab，
   新人读代码时"看目录就知道 App 在做什么"。
4. **`mascot/` 独立** —— IP 不是散落在各处的图片，是有归属的资产。

### 4.3 组件命名：去掉通用感，加品牌前缀

现在的组件名（`SettingsItem`、`EngineActionButton`、`EngineSectionHeader`）是**中性的**。
自有设计系统的组件应有品牌前缀，这既是工程规范，也是身份声明：

```kotlin
// 改为
ZayuCard      / ZayuListItem   / ZayuChip
ZayuRing      （环形进度 + 光晕）
ZayuSheet     （统一 BottomSheet 外壳，含拖拽把手与玻璃背景）
ZayuMascot    （IP 形象，带状态：Idle / Loading / Happy / Sad）
ZayuEmpty     （空状态，内嵌 mascot）
```

### 4.4 迁移策略（低风险）

**不要一次性大搬家**（263 个文件全挪 = 一次改崩整个仓库）。
分三步：
1. **先建 `design/` 与新组件**（纯新增，零风险）—— 新的 UI 用新组件，老的保持不动
2. **再建 `mascot/`**，在空状态/加载/失败三处接入（改动局限在 3 个文件）
3. **最后按 Tab 逐个迁移 `feature/`** —— 每次只动一个 Tab，改完编译 + 真机验证再进下一个

**迁移期间双轨并存是正常的**，不要追求"一次重构干净"。

## 5. IP 形象植入（「吃瓜少女」）

### 5.1 状态化使用

同一个形象，**四种状态**，覆盖关键情绪节点：

| 状态 | 出现场景 | 形象表现 | 文案 |
|---|---|---|---|
| `Idle` | 空状态（无历史、无文件） | 抱着西瓜坐着，歪头 | 「这里空空的…要不要贴个链接试试？」 |
| `Loading` | 解析中 / 下载准备中 | 举着西瓜当伞转圈 | 「正在努力解锁…」 |
| `Happy` | 下载完成 / 解析成功 | 举西瓜欢呼 | 「搞定！瓜分给你 🍉」 |
| `Sad` | 解析失败 / 登录失效 | 西瓜裂了，眼泪 | 「呜呜，被防住了，再试一次？」 |

**技术实现**：`ZayuMascot(state: MascotState, size: Dp)` 单组件。
四种状态用同一张底图 + 不同的**装饰层**（伞、掌声波纹、裂痕、眼泪）叠加，
**不需要四套完整插画** —— 显著降低素材成本。

### 5.2 文案改写对照表

| 现在 | 改为 | 位置 |
|---|---|---|
| 提取码 | **暗号** | 输入框 label、提示 |
| 开始解析 | **🔓 解锁** | 主按钮 |
| 解析失败 | **呜呜，被防住了，重试一下？** | 错误提示 |
| 暂无下载任务 | **瓜田还没开张，去解锁点什么吧** | 空状态 |
| 解析中... | **正在撬门…** | 加载态 |
| 网络错误 | **网线被瓜藤缠住了，检查一下网络？** | 错误提示 |
| 登录已过期 | **身份过期了，重新登一下** | 账号失效 |

**纪律**：**调性统一但不滥用**。错误提示可以萌，但**技术性错误必须保留原始信息**
（如 HTTP 403 / errno -6）放在次要行 —— 用户报障时 AI 才能定位。
即：`主文案萌 + 次行技术码` 的双层结构。

## 6. 落地顺序建议

| 阶段 | 内容 | 风险 | 收益 |
|---|---|---|---|
| **S1** | 品牌色替换（§3.2）+ 圆角收敛（§3.3）+ 等宽数字（§3.5） | **极低**（改常量 + Color.kt） | 立竿见影：整体色调统一，立刻摆脱"默认蓝"观感 |
| **S2** | 导航改胶囊 + Tab 改名（§2.1） | 低（导航栏是独立组件） | 架构语义改善，最先被用户感知 |
| **S3** | 首页重构：剪贴板卡 + FAB + BottomSheet（§1.2） | 中（解析页是核心页，要保功能） | 彻底摆脱"解析工具"长相 |
| **S4** | 传输页环形进度 + 已折叠（§2.2） | 中（纯渲染层，数据已有） | 视觉冲击力最强的一项 |
| **S5** | IP 形象 + 文案改写（§5） | 低（3 个接入点） | 情感连接，成本最低的人格化 |
| **S6** | `design/` 与 `feature/` 结构重组（§4） | 中高（分 Tab 小步走） | 长期可维护性 + 架构独立性 |
| **S7** | 媒体库 + 跨盘搜索（§2.3） | 高（需要索引层与后台任务） | 从"工具"到"消费产品"的质变 |

**建议先做 S1 + S2**：改动小、风险低、视觉收益立刻可见，可以先发一版看用户反应，
再决定后续投入。S7 属于产品方向级决策，建议单独评估（涉及存储占用与后台耗电）。
